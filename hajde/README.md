# ejaBashkohu

Social table-reservation platform for Kosovo — discover open tables, join rides and trips, chat with hosts, and manage bookings.

Live site: [https://ejabashkohu.com](https://ejabashkohu.com)

## Tech stack

| Layer | Technology |
|-------|------------|
| Frontend | React 19 + Vite |
| Backend | Supabase (Postgres, Auth, Storage, Realtime, Edge Functions) |
| Hosting | Cloudflare Pages (`ejabashkohu` project) |
| i18n | Albanian (sq), English (en), German (de), Macedonian (mk) |

## Repository layout

```
hajde/
├── src/                  # React app (HajdeApp.jsx, components, hooks, i18n, API layer)
├── supabase/
│   ├── migrations/       # SQL migrations (apply manually — see below)
│   └── functions/        # Deno Edge Functions
├── verification/         # Playwright/Node verification scripts
├── scripts/              # One-off dev/QA scripts
├── public/               # Static assets (icons, OG image, manifest)
└── dist/                 # Production build output (gitignored — generated by npm run build)
```

## Environment variables

Create `hajde/.env` from `.env.example`:

| Variable | Description |
|----------|-------------|
| `VITE_SUPABASE_URL` | Supabase project URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase anon/public key |

Values are in **Supabase Dashboard → Project Settings → API** for project `upxxfhvgbmddhyebaiug`.

Never commit `.env`. Edge Function secrets (`SUPABASE_SERVICE_ROLE_KEY`, `SMTP_PASSWORD`, etc.) are configured in the Supabase Dashboard, not in this repo.

## Run locally

```bash
cd hajde
npm install
cp .env.example .env   # then fill in values
npm run dev            # http://localhost:5173
```

Preview production build:

```bash
npm run build
npm run preview        # http://localhost:4173
```

## Deploy to production

Deployment is manual via Wrangler (not connected to GitHub CI yet):

```bash
cd hajde
npm run build
npx wrangler pages deploy dist --project-name ejabashkohu --branch production
```

**Important:** `--branch production` is required to update the live custom domain `ejabashkohu.com`. Deploying with `--branch main` (or omitting the flag) publishes to a preview URL only and does **not** update the live site.

Verify the live bundle after deploy:

```bash
curl -s https://ejabashkohu.com | grep -oE 'index-[A-Za-z0-9_-]+\.js'
```

## Database migrations

SQL migrations live in `supabase/migrations/`. Apply them **manually** via the Supabase SQL Editor (Dashboard → SQL → New query → paste migration → Run).

The Supabase CLI account used on this project does not have sufficient privileges for `supabase db push` against the linked remote. Always apply migrations in filename order and verify with the relevant script under `verification/` when available.

## Edge Functions

Functions in `supabase/functions/`:

| Function | Purpose |
|----------|---------|
| `check-email-domain` | MX record validation on signup |
| `notify-email` | Transactional email via SMTP |
| `notify-ban` | Email notification when a user is banned |
| `delete-banned-user` | Hard-delete banned user data |

Deploy a function:

```bash
supabase functions deploy <function-name> --project-ref upxxfhvgbmddhyebaiug
```

Example:

```bash
supabase functions deploy notify-email --project-ref upxxfhvgbmddhyebaiug
```

Function secrets (SMTP credentials, service role key) are set in Supabase Dashboard → Edge Functions → Secrets, not in git.

## Verification scripts

End-to-end and i18n checks live under `verification/`. Run against local preview or production:

```bash
node verification/verify-phase7-i18n.mjs https://ejabashkohu.com
```

Evidence output goes to `verification/evidence/` (gitignored).

Optional env vars for test scripts: `E2E_EMAIL`, `E2E_PASSWORD`, `SUPABASE_SERVICE_ROLE_KEY` (admin-only tests).
